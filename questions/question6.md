# 문제 6

## 막혔던 부분

```
 뭘 해결해야 되는가?
 personType이 user이면 occupation이 존재하고, admin이면 role이 존재한다
 criteria는 admin이면 name,age,role
 user이면 name,age,occupation만 있어야함
```

## 해결을 위해 필요한 키워드 1개

함수 오버로딩

## 키워드 단순 학습

함수 오버로딩?
하나의 함수를 여러 버전으로 만드는 방식
js에는 없고 ts에만 존재함

함수 선언부랑 구현부가 있는데
다르게 선언한 버전의 개수만큼 구현부도 그 개수만큼 생성하는 것이 아니라
1개의 함수 구현부 내부에서 옵셔널 연산자를 사용(파라미터에서)해서
조건문으로 버전을 필터링 하는 방식임

## 문제에 적용시켜 해결한 방법

## 키워드 심화학습 (생각해볼만한 질문)

(Level 1 - 용어) personType: "admin" | "user"라고 쓰면, 타입스크립트 입장에서 "유입된 인자가 admin일 때 리턴값은 무조건 Admin[]이다"라는 확신을 가질 수 있을까요? 아니면 여전히 둘 중 하나라고 생각할까요?

A. 확신을 못가질 것 같습니다. 둘중 하나라고 생각하겠죠

(Level 2 - 설명) 오버로드는 **'입력과 출력의 짝(Pairing)'**을 맺어주는 과정입니다. 학습자님의 유니온 방식은 왜 이 '짝'을 맺어주는 데 실패했을까요? (힌트: 입력을 'user'로 넣어도 출력 타입이 Admin[] | User[]로 나오는 현상을 생각해보세요.)

A. 짝을 맺어준게 아니라 그냥 둘중 하나로 나오게 방치했기 때문이에요 personType: "admin" | "user"도 그렇고, 함수의 반환 타입을 Admin[] | User[]로 둔 것도 모두요.
admin이 들어왔을 때만 Admin을 반환시키도록 해야되는데 그렇지 못해서 실패했다고 생각합니다.

(Level 2 - 설명) 타입스크립트에서 오버로드를 정의할 때, 실제 코드가 작성된 부분(구현부) 위에 선언하는 코드들을 **'호출 시그니처(Call Signature)'**라고 합니다. 왜 구현부 자체에는 복잡한 유니온 타입을 써야만 할까요?

A. 하나의 함수 구현 하나로 모든 선언 시그니처들을 커버할 수 있어야 하기 때문이라고 생각합니다.
그런데 Person이라고 적은 것은 Person이 Admin | User이기 때문인가요? 만약 Person 타입을 따로 지정하지 않았다면 Admin | User로 쓰는게 맞는 방식일까요? 궁금합니다.

(Level 3 - 적용) 만약 filterPersons(..., "user", { role: "admin" })이라고 호출한다면, 학습자님의 유니온 방식은 에러를 낼까요? 아니면 통과시킬까요? (이게 안 막히는 이유가 오버로드가 필요한 진짜 이유입니다.)

- 에러를 내지 못할 것 같습니다. Partial<User> | Partial<Admin>이었기 때문에 잘 맞는다고 생각하고 에러가 나지 않아요.

(Level 4 - 변형) 보너스 문제인 getObjectKeys(criteria)를 만들 때, Object.keys()가 기본적으로 string[]을 반환하는 이유를 '타입 안정성' 관점에서 설명할 수 있나요? (이걸 해결하려면 제네릭이 왜 필요한지 연결됩니다.)
