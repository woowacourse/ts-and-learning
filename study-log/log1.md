### 1. 첫 학습 전략 설계

- 어떤 전략으로 학습하기로 했는가?
- 그 전략을 선택한 이유는?
- 실제로 어떻게 학습했는지 디테일한 과정을 써보세요.

우선 기존에 해오던 학습 전략을 기반으로 시작하고자 하였습니다.
이 전략을 선택한 이유는 온고지신하게 기존에 해오던 학습 전략 위에 새로운 전략을 덧붙이는 것이 완전 새로운 전략을 세우는 것보다 더 효과적일 것이라고 생각했기 때문입니다.
이에 따라서 우선 기존 방식에서 부족해보이는 부분을 찾고자 하였습니다.

우선적으로 제가 알고있는 지식과 필요한 지식이 무엇인지를 알기 위해서 우선적으로 공부 없이 문제를 풀어보았습니다.
그러다가 #4번 문제에서 is 키워드에 대해서 기억이 나지 않아 공부를 진행하게 되었습니다.
공부 자료는 기존에 스터디를 진행하면서 정리했던 노트 정리를 참고하였습니다.

단순히 노트를 읽는 것 보다는 AI를 통해서 노트정리를 기반으로 해당 내용을 전부 확인할 수 있는 주관식 문제를 만들어달라고 요청하였고, 제가 현재 알고있는 지식과 기억나지 않는 지식을 확인하도록 하였습니다.
이후 기억나지 않는 부분에 대해서 다시 공부하는 방식으로 공부를 진행하였습니다.

### 2. 전략 평가

- 효과적이었던 것과 그 이유
- 비효과적이었던 것과 그 이유

효과적이었던 점은 AI를 통해서 주관식 문제를 만들어보는 것이었습니다.
단순히 노트정리를 하나씩 읽어가는 것 보다 제가 알고있는 지식과 기억나지 않는 지식을 확인하는 과정을 통해서 정해진 시간동안 제가 공부해야하는 범위를 좁히고 명확하게 하는데 도움이 되었습니다.

비효과적이었던 점은 공부 자료로 노트 정리를 활용한 것이었습니다.
노트 정리는 제가 스터디를 진행하면서 정리했던 내용이기에 제가 이해한 수준에서 정리가 되어있었고, 지식의 확장이나 심화된 내용이 부족하였습니다.
공부했던 개념들을 다시한번 상기하는 현재 단계에서는 해당 노트 정리가 도움이 되었지만, 앞으로 심화된 개념들을 공부할 때는 좀 더 확장된 자료가 필요할 것 같습니다.

### 3. AI 피드백

- 자신의 학습 전략에 대해 AI에게 피드백을 요청하고, 유용했던 제안 1가지 이상 기록

단순히 텍스트를 읽는 것에만 머무는 것이 아니라, 피드백 루프에 직접 코드를 구현해보는 단계까지 나아가야 합니다.

<details>
<summary>AI 피드백</summary>

✅ 강점

1. 진단 우선 접근 (Diagnosis First)
   문제를 먼저 풀어보고 모르는 것을 확인한 것은 Ultralearning의 핵심 원칙인 "직접성(Directness)" 과 일치합니다. 무엇을 모르는지 모르는 상태에서 처음부터 공부하는 것보다, 실제 문제에 부딪혀 공백을 먼저 발견하는 방식은 학습 에너지 낭비를 줄여줍니다.
2. 능동적 인출 (Active Recall)
   노트를 수동적으로 읽는 대신 AI로 주관식 문제를 만들어 스스로 인출한 것은, 제가 Ultralearning에서 강조하는 "직접적 피드백 루프" 를 만든 좋은 예입니다. 인출 연습은 단순 재독보다 기억 강화 효과가 훨씬 높다는 것이 연구로도 증명되어 있습니다.
3. 기존 전략 위에 쌓기
   완전히 새로운 시스템을 만들려다 실행하지 못하는 것보다, 기존 방식에서 출발한 것은 현실적으로 현명한 선택입니다.

❌ 약점

1. 노트가 학습의 천장이 됨
   스스로도 인식했듯이, 본인이 이해한 수준으로 작성된 노트는 이미 알고 있는 것의 반복 에 그칠 가능성이 높습니다. 이것은 Ericsson이 말한 "편안한 반복"의 함정입니다. 심화 개념에 도달하려면 노트 밖으로 나가야 합니다.
2. 피드백의 품질이 검증되지 않음
   AI가 만든 문제에 스스로 답하는 구조는 좋지만, 정답의 기준이 본인의 노트 안에 갇혀 있습니다. 틀린 이유를 파악하거나 더 깊은 이해로 나아가는 외부 피드백 루프가 없습니다.
3. 학습이 "상기(Review)" 수준에 머무름
   현재 방식은 알던 것을 다시 떠올리는 데는 효과적이지만, 새로운 멘탈 모델을 형성하는 단계로 나아가지 못하고 있습니다.

문제의 핵심 진단
현재 학습 구조를 도식화하면 이렇습니다.

```
[노트 읽기] → [AI 문제풀기] → [모르는 부분 다시 읽기]
    ↑
  이 루프 전체가 "노트"라는 닫힌 시스템 안에 있음
```

개념을 아는 것과 개념을 사용할 수 있는 것은 다릅니다. 현재 방식은 "인식(recognition)" 을 훈련하지만, 실제 개발에서 필요한 것은 "생성(generation)" 입니다.

💡 개선안: "문제 → 구현 → 설명" 3단계 루프
AI 문제 풀기를 텍스트 답변에서 실제 코드 구현으로 바꾸는 것입니다.
[기존 방식]
모르는 개념 발견 → AI 주관식 문제 → 텍스트로 답변 → 노트 재독

[개선된 방식]
모르는 개념 발견 → AI 구현 문제 → 코드로 직접 구현 → 틀린 이유 분석
