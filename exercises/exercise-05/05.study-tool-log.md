문제 번호: [ #05 ]

1. 이 문제가 학습하길 의도하는 개념(내 추측)
[ Partial ]
- 문제에서 아래 부분이 핵심인듯 
  - Without duplicating type structures, modify
    타입 구조를 중복 정의하지 않고
  - pass only those criteria which are needed,
    필요한 조건만 전달할 수 있도록 만들고
  - User를 다시 제정의 하지 않고 재사용 하기
- 한번 걸러서 User이긴 하니까 User의 부분 집합이면 될 것 같다

2. 풀이 접근
[ Partial, Utility ]
- Utility 타입
  - 이미 정의되어 있는 타입 구조를 변경하고 재사용하고 싶을때 사용하는 타입
  - 타입스크립트에서 미리 정의해 놓은 내장 타입
- Partial
  - 특정 타입의 모든 속성을 모든 옵션 속성으로 변환한 타입을 생성해줌
  - 주로 HTTP PUT 처럼 데이터를 수정하는 REST API 를 전송할때 종종 사용되는 타입
  - ```Partial<대상타입>```
- Pick
  - 이미 존재하는 특정 타입의 속성을 뽑아서 새로운 타입을 만들어 낼떄 사용
- Omit
  - 특정 타입에서 속성 몇개를 제외한 나머지 속성으로 새로운 타입을 생성할때 사용하는 타입
- Exclude
  - 유니언 타입을 구성하는 특정 타입을 제외할 때 사용
  - 유니언 타입을 변형
- Record
  - 타입 1개를 속성의 키로 받고 다른 타입 1개를 속성값으로 받아 객체 타입으로 변환
  ```
    type HeroNames = 'thor' | 'hulk';
    type HeroProfie = { skill: string; age: number };
    Record<HeroNames, HeroProfie>;
  ```
- criteria
  - 조건: 어떤 데이터를 선별 / 필터링 / 검색하기 위한 기준 값

3. 실제 문제 의도 (ai)
[ Type Reuse, Type Transformation ]
- 타입의 의미를 상황에 맞게 변형해서 재사용
- Utility Type을 이용해서 타입의 ‘의미’를 바꾸는 능력

4. 틀린 이유 (정리)
[ Data vs Criteria Confusion ]
- 부분 집합이면 된다 -> 맞지만 표면적인 이해고
- 왜 부분 집합이여야 하나, 그게 어떤 상황(조건 vs 데이터) 때문인지를 생각해야함
- User: 실제 데이터 모델
- criteria: 검색 조건
