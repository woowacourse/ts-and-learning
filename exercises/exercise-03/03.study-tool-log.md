문제 번호: [ #03 ]

1. 이 문제가 학습하길 의도하는 개념(내 추측)
[ union ]
- union 타입의 경우 타입스크립트 언어 차원에서 공통되는 property에 접근이 바로 가능하고
  공통되지 않는 property의 경우 정체(refine) 해야 접근이 가능함을 드러내는 문제 같다
  
2. 풀이 접근
[ union, refine ]
- union
  - 유니온 사용시 주의 할 점
    - A | B 인 경우 A의 속성과 B 속성 당연히 제공해주지 않을까? 착각함
    - logPerson 함수에 넘어오는 argument 의 경우 User일수도 있고 Admin 일수도 있음
    - 이떄 User 인데 role에 접근하려고 했을때 타입 에러가 표시되지 않았다면 
      실제로 코드를  실행했을때만 에러를 발견할수 있었을것
    - 이처럼 함수의 파라미터에 유니언 타입을 사용하면 함수에 어떤 값이 들어올지 알수 없기때문에 가장 안전한 방식으로 타입의 속성과 API를 자동완성해줌
    - 함수 내부에서 파라미터의 종류에 따라 특정 로직을 실행하고 싶다면 연산자 in을 이용해서 작성
- if(person.role)
  - 이 코드는 role이라는 속성이 존재한다는걸 타입스크립트에서 보장하는 조건이 아님
- refine
  - 타입을 구체적으로 좁히는 행위
  - 개념적 용어(공식 키워드 아님)
- 타입 가드
  - 타입 스크립트가 공식적으로 narrowing 을 인정하는 패턴

3. 실제 문제 의도 (ai)
[ type narrowing ]
- 타입스크립트의 타입 좁히기(narrowing) 규칙을 이해시키는 것

- 타입 가드
  ```
    typeof x === 'string'
    'role' in obj
    instanceof SomeClass
  ```
  - 여러개의 타입으로 지정된 값을 특정 위치에서 원하는 타입으로 구분하는 것
  - 타입 시스템 관점에서는 넓은 타입에서 좁은 타입으로 타입 범위를 좁히는다는 의미
  - 여러 타입이 있을때 내가 원하는 타입을 뽑기 위해 다른 타입을 막아낸다(가드한다)는 의미

  - 방법
    - 타입 단언
    - typeof 연산자
    - instanceof 연산자
    - in 연산자
      - 객체에 속성이 있는지 확인
      - 타입 가드로 특정 타입을 걸러내려면 해당 타입이 다른 타입과 구분되는 유일한 특징을 조건로로 으로 걸어야함
