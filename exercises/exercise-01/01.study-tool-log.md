2. 풀이 접근
[ 객체 타입 alias 작성 ]
- type
  - 특정 타입이나 인터페이스를 참조할수 있는 타입 변수
  - 타입에 의미를 부여해 별도의 이름으로 부르는 것
  - 반복되는 타입 코드를 줄여줄수 있다
  - 타입을 선언하고 나서 다시 다른 타입을 할당할수 없음
  ?: type alias와 interface 어느걸 사용하는게 좋을까?
    - 에디터
      - type alias: 객체 내부의 타입이 바로 보인다
      - interface: 이름만 나옴
    - 사용할수 있는 타입 차이
      - interface: 객체 타입 정의
      - type: 유니언, 인터섹션 타입 가능
    - 타입 확장
      - 이미 정의 되어 있는 타입들을 조립해서 더큰 의미의 타입을 생성
      - interface: extends 사용
        - 선언 병합 가능: 동일한 이름으로 인터페이스를 선언하면 인터페이스 내용을 합치는 특성
      - type: 인터섹션
    - 사용처
      - 타입 별칭으로만 타입 정의가 가능한 곳에서는 타입 별칭을 사용하고 
        백엔드와의 인터페이스를 정의하는 곳에서는 인터페이스를 이용하자 by 쉽게 시작하는 타입 스크립트
      - 타입별칭만 가능
        - 제네릭
          ```type A<T> = T extends string ? string: number;```
        - 유틸리티 타입입
        - 맵드 타입
      - 백엔드와 인터페이스 정의
        - 여기서의 인터페이스란: 백엔드에서 프런트엔드로 데이터를 어떻게 넘길지 정의
        - 서비스 요구사항이 변경되어 화면에 노출해야하는 데이터 구조가 바뀌었을때
          사용자 role, address 등이 추가되거나 다른 객체 정보와 결합되어 표시되어야 한다면 기존의 타입 확장이라는 측면에서 인터페이스로 정의하는 것이 더 수월함

- unknown 
  - top 
  - 타입을 미리 알 수 없는 어떤 값이 있을때 any 대신 unknown 을 사욯자
  - any 처럼 unknwon 도 모든 값을 대표하지만, unknown  타임의 값을 검하새 정제(refine) 하기 전까지는 타입스크립트가 unknown 타입의 값을 사요할수 없게 강제 한다
  - 지원하는 연산자 - 비교, 반전, typeof, instanceof
