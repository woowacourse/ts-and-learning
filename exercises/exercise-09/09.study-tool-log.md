2. 풀이 접근
[ generic, union, discrimiated union ]
- success 인 경우와 error 인 경우를 각각 만들고 union으로 결합시킴
- union
  - status가 일종의 구별된 union 의 key 처럼 사용되는 듯 하다
  - 여러개의 타입을 특정 속성의 유무가 아니라 특정 속성 값으로 구분하는 타입 가드 문법

- Sum Type(Tagged Union), Algebric Data Type(ADT), 상태 전이, 상태 머신(State Machine), 오케스트레이션
  = redux의 action 발행으로 상태값 변경의 유형을 제한하는 것과 유사하다고 느낌
  - 데이터를 경우(case)로 나눠서 표현하는 방식
  - 잘못된 상태를 아예 만들수 없게 만들기 위해서
  - 여러 상태중 하나만 가질수 있게 강제하는 모델

3. 실제 문제 의도 (ai)
[ generic, discrimiated union ]
- 중복된 타입을 제거하고, 제네릭으로 재사용 가능한 API 응답 모델 만들기
- generic 으로 data을 외부에서 주입
- discrimiated union 으로 success/error 분기 모델링
