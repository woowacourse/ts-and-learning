## **도구 이름**

TS-JS 변환기

## **도구 유형** (예: GPTs, gems, Claude Code(skill, command, agent, ...) Chrome Extension, CLI, 웹사이트 등)

Gemini Canvas

## **해결하려는 문제**: 어떤 학습 상의 불편/문제를 해결하려 했는가?

TypeScript를 처음 학습할 때, TS 문법이 실제 JavaScript 코드로 어떻게 변환되는지 직관적으로 체감하기 어려웠다. 특히 TypeScript에서 에러로 잡아주는 코드가 JavaScript 환경에서는 왜 위험한지, 두 환경의 차이를 실시간으로 비교하며 이해하기가 쉽지 않았다.

직접 JavaScript 코드를 다시 작성하며 비교해보기도 했지만, 이 과정은 반복적이고 비효율적이라고 느꼈다. 이렇게 진행해보니 TS와 JS의 차이를 한 번에 비교하며 이해할 수 있는 도구의 필요성을 느꼈다.

## **어떻게 만들었는가**: 간단한 제작 과정

이러한 문제를 해결하기 위해, TypeScript 코드를 입력하면 JavaScript 코드로 변환하고 두 환경의 차이를 함께 보여주는 도구를 제작했다.

작성한 TS 코드를 기반으로 대응되는 JS 코드를 생성하고, 각 코드가 실행될 때 어떤 차이가 발생하는지를 결과 중심으로 비교할 수 있도록 구성했다.

또한 입력된 코드 패턴을 분석하여, TypeScript 환경에서의 컴파일 에러 메시지 / JavaScript 환경에서의 실제 런타임 실행 결과를 각각 생성해 보여주도록 설계했다.

## **어떻게 도움이 되었는가**: 실제 사용 경험과 효과

단순히 문법을 암기하는 것이 아니라 JavaScript의 런타임 에러를 TypeScript가 어떻게 사전에 방지하는가라는 관점으로 학습 방향을 전환할 수 있었다.

특히 TypeScript에서는 에러로 표시되는 코드가 JavaScript에서는 조용히 undefined를 반환하며 실행되는 모습을 비교해보면서, TypeScript 도입의 필요성을 더욱 명확하게 이해하게 되었다.

또한 interface나 타입 선언이 JavaScript로 변환되는 과정에서 완전히 제거되는 것을 직접 확인하며, TypeScript는 런타임이 아닌 개발 단계에서 동작하는 도구라는 개념을 확실히 체감할 수 있었다.
